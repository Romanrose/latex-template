# Design Patterns

跨平台、跨技术栈仍然成立的可视化方法。这里记录可以迁移的方法，而不是某个作品的像素级样式。

## 1. 结论先行

标题先回答“所以呢”，主图再证明它。适用于新闻、报告和社媒卡片。参考：[USA Today](../items/usa-today-winters.md)、[The Pudding](../items/the-pudding.md)。

## 2. 一张主图，一个任务

主图只承担比较、趋势、分布或地理定位中的一个任务；其余内容退为上下文。适用于观点型图表和 Dashboard。

## 3. 分层标注

默认只展示结论、尺度和关键异常；把精确值、定义和方法放到 hover、展开或附注中。参考：[earth](../items/earth.md)、[Premier League Dashboard](../items/premier-league-opponent-profiling.md)。

## 4. 颜色只做三件事

用颜色区分组别、表示连续尺度、强调例外。页面其余部分保持低对比中性色，避免每个元素都争夺注意力。

## 5. 由宏观走向个人

先给全局模式，再通过搜索、筛选或具体片段让读者找到自己。参考：[USA Today](../items/usa-today-winters.md)、[聊天记录可视化](../items/xiaohongshu-chat-history.md)。

## 6. 视觉隐喻不能遮蔽数据

如果形状、插画或动效被移除后数据完全不可读，它只是装饰；好的数据艺术仍保留比较关系、类别与尺度。参考：[Data Sketches](../items/data-sketches.md)。

## 7. 复刻的正确边界

复刻信息架构、图表选择、间距、颜色角色和交互逻辑；不复制插画、品牌、文本、私有数据或未经许可的界面资产。
